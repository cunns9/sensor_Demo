Module 01 · Sound Sources

Making a sound out of thin air

There are no audio files anywhere in this page. Every drum hit is generated on the spot by the Web Audio API. Think of an OscillatorNode like a guitar string that, once plucked, keeps vibrating forever until something damps it. A GainNode is your hand landing on that string — it's just a volume knob you can automate over time.

A kick drum is a sine wave whose pitch drops fast (150Hz down to 40Hz) while its volume fades to near-silence in about a third of a second. That falling pitch is what makes it feel like a "thump" instead of a musical note.

// one kick drum, scheduled to play at an exact time
function playKick(time) {
  const osc = ctx.createOscillator();
  const gain = ctx.createGain();
  osc.frequency.setValueAtTime(150, time);
  osc.frequency.exponentialRampToValueAtTime(40, time + 0.15);
  gain.gain.setValueAtTime(1, time);
  gain.gain.exponentialRampToValueAtTime(0.001, time + 0.3);
  osc.connect(gain).connect(ctx.destination);
  osc.start(time);
  osc.stop(time + 0.3);
}

Snare, hi-hat, and clap use the same idea, but built from noise instead of a pure tone — random static run through a filter, which is exactly what a snare's rattling wires sound like.

Module 02 · State

The grid is just a checklist

Underneath those 64 little circles is nothing fancier than four rows of true/false values — sixteen slots per row, like an ice cube tray that's either filled or empty in each compartment. The machine doesn't know what a "pattern" looks like. It only knows this:

const pattern = {
  kick:  [true, false, false, false, /* ...16 total */],
  snare: [false, false, false, false, /* ... */],
  hihat: [true, false, true,  false, /* ... */],
  clap:  [false, false, false, false, /* ... */],
};

Clicking a circle just flips one array value and toggles a CSS class so it lights up. Everything about "what the beat sounds like" lives in this one plain object — the audio code below never has to know it exists as a grid at all.

Module 03 · Timing

Why you can't just use setInterval

The obvious idea: call setInterval every "beat," and play a sound each time it fires. The problem is that JavaScript timers are more like a distracted friend keeping a beat by ear than a metronome — the browser can pause them for a few milliseconds whenever it's busy with something else, and a few milliseconds of drift per beat turns into an obviously wobbly rhythm within seconds.

The fix — the same one real drum machine software has used for years — is to stop trying to make the *timer* precise, and instead use it only as a reminder to plan ahead. Every 25 milliseconds, the scheduler looks at the actual audio clock (which is sample-accurate) and asks: "which notes fall in the next tenth of a second?" It schedules those notes for their exact future moment, then goes back to sleep.

// runs every 25ms, but schedules notes with sample-accurate timing
function scheduler() {
  while (nextNoteTime < ctx.currentTime + 0.1) {
    scheduleStep(currentStep, nextNoteTime); // exact time, not "now"
    const secondsPerBeat = 60 / bpm;
    nextNoteTime += 0.25 * secondsPerBeat; // advance one 16th note
    currentStep = (currentStep + 1) % 16;
  }
  setTimeout(scheduler, 25);
}

Analogy: instead of reacting the instant a beat is due, this hands the audio engine a written schedule slightly ahead of time — "play this at exactly 1.375 seconds" — so it never has to guess.

Module 04 · Visual Feedback

Watching the beat move

The scheduler above only cares about sound — it happily schedules notes a tenth of a second before you hear them, which is too early for the on-screen playhead to jump ahead too. So drawing the moving highlight is a separate, second loop, running once per animation frame, that waits until each scheduled note's time has actually arrived before lighting up that column.

// runs on every animation frame — lags the scheduler on purpose
function drawPlayhead() {
  while (scheduledSteps.length && scheduledSteps[0].time < ctx.currentTime) {
    highlightStep(scheduledSteps.shift().step);
  }
  requestAnimationFrame(drawPlayhead);
}

This split — plan sound early, reveal it visually only when it's truly due — is what keeps the glowing step lined up with what you actually hear, instead of visibly running ahead of the beat.

Module 05 · Wiring It Up

Turning clicks into a working machine

The rest is plumbing: a click on a circle flips that step's boolean and toggles a class; the tempo slider just updates the bpm variable the scheduler already reads; Play builds the audio context and starts the scheduler loop, Stop clears it.

One catch every browser enforces: an AudioContext can't make sound until the page has felt at least one real click or tap. That's a deliberate anti-annoyance rule — like a jukebox that won't play until someone puts a coin in, so no page can start blaring audio the moment it loads.

function ensureAudio() {
  if (!ctx) ctx = new AudioContext();
  if (ctx.state === 'suspended') ctx.resume();
  return ctx;
}

That's the whole instrument. Nothing above is simplified for the page — it's copied straight from the script running the machine at the top.
